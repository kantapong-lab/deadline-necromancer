# Client modules (FE)

All under `app/public/**` (FE). No build step, no new dependency, no CDN. Event contract: [endpoints/voice.md](endpoints/voice.md). The server is authoritative; client mute (`track.enabled`, closing connections) is courtesy plus defence in depth (AC-17, AC-10 receiver drop).

## Player: `app/public/voice.js` (classic script, sets `window.Voice`)
Loaded by `<script src="/voice.js">` in `app/public/index.html` after `common.js`. FE also edits `index.html` for the button, mute button, hint text and speaking indicator (UI design per `design.md` if the Designer produced one; this contract fixes behaviour only). Do not edit `common.js` (http-parity pins its hash).
- API (suggested): `Voice.init({socket, getState})`, `Voice.onState(st)` called from the existing `socket.on('state')`, `Voice.toggle()`, `Voice.toggleMute()`, `Voice.status()` -> `{supported, hint, on, muted, permit, speaking:{[pid]:true}}` for the render function.
- **Feature detect (AC-13):** if `!window.isSecureContext || !navigator.mediaDevices?.getUserMedia || !window.RTCPeerConnection` -> button hidden or disabled with hint `ต้องใช้ HTTPS`. `getUserMedia` rejection `NotAllowedError`/`SecurityError` -> `ต้องอนุญาตไมโครโฟน`; `NotFoundError`/`OverconstrainedError`/no audio input -> `ไม่พบไมโครโฟน`. The game stays fully playable; no `console.error`, no unhandled rejection (every async path try/catch or `.catch`), no throw into `socket.on` callbacks. (`tools/e2e-3d-check.js` records `console.error` and page errors as failures.)
- **Capture (AC-1):** on tap, `getUserMedia({audio:{echoCancellation:true, noiseSuppression:true, autoGainControl:true}})` (must run inside the tap handler for iOS), then `voice:on {on:true}`; ack gives `iceServers`, `permit`, `peers`. Turning voice off: close everything, stop tracks, `voice:on {on:false}`.
- **Outbound (speaker role):** while `permit && micOn`, for each `peers[i]` without an open connection of the same `gen`: `RTCPeerConnection({iceServers})`, `addTrack(micTrack)`, `createOffer`, `v:sig` offer, trickle ICE (queue candidates until the remote description is set). A peer whose `gen` changed or that left `peers`: close and re-offer if present. `voice:permit {false}`: close ALL outbound within the same tick (AC-8, AC-9). `voice:permit {true}`: offer to every peer again.
- **Inbound (listener role, AC-3):** `v:sig` offer from `from`: close any existing inbound connection from that pid, new connection (no local tracks), set remote, answer, relay ICE. `ontrack`: hidden `<audio autoplay playsinline>` with `srcObject`. `voice:drop {pid}` or the inbound state `failed`/`closed`: close and remove the element within 1 s (AC-10). Ignore any `v:sig` with an unknown `kind` or missing `from`.
- **Mute button (AC-17):** `track.enabled = !muted` on the mic track; visible only while voice is on. Co-located players use it to avoid echo (assumption in `ac.md`).
- **Speaking indicator (AC-19):** `AnalyserNode` on each live inbound stream and on the local mic (only when `permit && !muted`); level threshold with a short hold. Indicator for a pid exists only while its inbound connection is open (so only currently permitted speakers, and gone after `voice:drop`). Never inferred from `state`.
- **Reconnect (AC-14):** on socket `connect` after the first, once `player:join` with the stored token acks ok (existing code in `index.js` flow), and whenever `state.youId` changes: close all connections, then if voice was on `voice:on {on:true}` again.

## Mod3D: `app/public/mod3d/voice.js` (ES module, native Web Audio, no THREE import)
Imported by `app/public/mod3d.html` next to `createDirector`. Listener only (never captures, never sends audio).
- `createModVoice({socket, deskPos, onSpeaking})` -> `{enable(), rehandshake(), update(camera), dispose()}`. `deskPos(pid, out)` is supplied by `mod3d.html` and writes the world position of the desk group `desks[pid].g` into `out` (`{x,y,z}`) and returns false if there is no desk. Positions come from the moving group, never fixed coordinates (seats move: `mod3d.html:719`).
- **Click to enable sound (AC-18):** `mod3d.html` shows an overlay on load; the click handler calls `enable()`: creates/resumes the `AudioContext`, then `voice:on {on:true}`. No `voice:on` (so no speaker offers) before the click, hence no voice before the context is unlocked. `rehandshake()` is called from the existing `socket.on('connect')` handler after `mod:join` acks ok (AC-15); it re-sends `voice:on` only if sound was enabled.
- **Inbound:** `v:sig` offer from a pid -> recvonly connection, answer with `to: pid`. `ontrack`: attach the stream to a muted `<audio>` element first (Chromium needs it before Web Audio outputs a remote stream [verify in current Chrome]), then `MediaStreamSource -> PannerNode -> context.destination`. `PannerNode`: `panningModel:'HRTF'`, `distanceModel:'linear'`, `refDistance` about 10, low `rolloffFactor` (orthographic top-down camera: left/right pan is the cue; FE tunes). `update(camera)` per frame: listener position/orientation from the camera, each panner from `deskPos` (AC-2).
- **Mute / drop (AC-10):** `voice:drop {pid}` closes that connection and disconnects its nodes within 1 s; a pid with no open connection has no panner. Mod3D never hears a pid unless the server relayed its offer.
- **Speaking indicator (AC-19):** `AnalyserNode` per live stream -> `onSpeaking(pid, bool)`; `mod3d.html` renders it on the desk label. Same rule: only for pids with an open inbound connection.
- Errors never reach `console.error`; all promises caught (e2e watcher above).
