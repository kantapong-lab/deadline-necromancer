Theme must stay office/client (Thai text, same style as existing cards). Rules below were agreed with the product owner one by one; do not change them, ask if something is unclear.

1) #16 MEETING PURGE (ล้างประชุมประจำ). Real-world inspiration: Shopify cut recurring meetings in Jan 2023 (about 10,000 calendar events). Rule: on the day this card is active, each player may send max 3 public morning-chat messages, each max 30 characters (emoji from EMOJIS do not count; a message over 30 chars is rejected and does NOT use up quota). Dark faction night chat (darkSay) is NOT limited. UI shows remaining message count. NDA Silence behaviour unchanged. Files: src/engine/chat.js, views.js, public client.

2) #17 MORE HANDS ON DECK (ทีมเสริมมาช่วย). Inspiration: Brooks's law. Rule: at event draw (morning), pick k = max(1, floor(aliveCount / 4)) random alive players as the "extra team"; announce their NAMES publicly; their vote weight is 0 for that day (they can still vote and be voted for). Reset next night via the existing zeroNext mechanism (set p.zero = true in drawEvent; closeNight already shifts zero flags). Never repeats (card drawn once per game).

3) #18 UAT TOO LATE (ทดสอบก่อนส่งงานไม่กี่วัน). Inspiration: HealthCare.gov 2013 late end-to-end testing. Rule: AFTER the day vote closes (after closeVote, using alive players at that moment), pick exactly 3 random alive players, publicly announce their names and the TRUTHFUL result "มีฝ่ายมืดอย่างน้อย 1 คน" or "ไม่มีฝ่ายมืด". Result always true (not affected by Honeypot/Alibi/Overpromise). Pattern like replyAllLeak() in src/engine/events.js but fired from closeVote. Edge: if fewer than 3 alive, use all alive.

4) #19 CLIENT REDESIGN (ลูกค้าขอแก้ดีไซน์). Inspiration: Sydney Opera House redesign overruns. Rule: the vote has TWO rounds that day. After round 1 closes, announce only the interim tally (votes per player + Skip count) — NO names of who voted whom; nobody is ejected yet. Between rounds public chat is allowed (new interim phase, Moderator gets a button to open round 2 with the normal timing controls). Round 2: players may change votes; a player who does not re-vote keeps their round-1 vote. The final result is round 2 only: Blame Shifting / Exit Scam trap checks, Skip penalty/streak, Mana +2 for ejecting dark, voteResult lines are all computed from round 2 only. Files: src/engine/phases.js, vote.js, views.js, mod-view.js, server handlers + moderator UI.

5) #20 STATUS PAGE DOWN (หน้าสถานะล่มไปด้วย). Inspiration: AWS S3 outage Feb 2017 (AWS's own status page failed because it depended on S3). Rule: at event draw (morning), the full night report (curse blocked / "คำสาปถูกสกัด" messages, bug −1, Mana line, trap-triggered messages) is NOT published; instead it is delivered privately (via the existing `intel[pid]` channel) to exactly ONE random alive player, the "on-call engineer" (วิศวกรเวร), fixed at 1 for every room size. Everyone else sees only the names of players who got Burnout. Publicly announce only: "มีวิศวกรเวร 1 คนได้รับสรุปเมื่อคืน (ไม่บอกชื่อ)". The on-call identity is NEVER announced (so players can bluff/claim). The on-call player can tell the truth or lie. The Mana bar on screen stays visible as normal. Moderator view still shows the full report. Chaos Intern "Reply All" may leak the on-call's note — acceptable. This needs the night report lines to be classified (public: Burnout names; status: the rest) in night-resolve.js.
